title: ワークスペースとフォルダー

---

**ワークスペース** は、会話が作業するフォルダーと、その外で触れられるもの（ほかのフォルダー、Web サイト、シークレット、スクリプト）のまとまりです。会話はそれぞれ 1 つのワークスペースを使います。選んでいない会話は **Default** ワークスペースを使います。

## 会話のワークスペースを選ぶ {#pick-a-workspace-for-a-conversation}

メッセージ欄の下にあるワークスペースの選択メニューを使います。ワークスペースの一覧と **New workspace** が表示されます。ほかを選んでいない会話はすべて **Default** ワークスペースを使います。

## ワークスペースを編集する {#edit-a-workspace}

**Settings › Workspaces** を開き、ワークスペースの **⋯** メニューから **Edit** を選ぶか、**New** で作成します。ダイアログには名前、メインの **Folder**（新しいファイル、スクリーンショット、成果物の保存先）、そして触れられる範囲の種類ごとに 1 行があります。各行は現在の設定を示し、クリックするとそのページが開きます。

| ページ | 設定内容 |
|---|---|
| **Allowed folders** | このワークスペースが使えるほかのフォルダーと、それぞれのアクセス権。ほかのワークスペースからは触れられません。 |
| **Sites** | 使える Web サイト：**None**、**Listed sites**、**Any site**。また、[内蔵ブラウザー](../use/browser.md#allow-a-site) が一覧の各サイトをどう扱うか。 |
| **Secrets** | 保存したシークレットのうち、Web リクエストで送ってよいもの。モデルにシークレットの値は見えません。 |
| **Scripts and commands** | Python と Node.js の **Scripts**、および **Commands** を実行できるか。 |
| **Environment variables** | スクリプトとコマンドに渡す値。 |

**Sites** の選択肢の意味：

- **None**：Web 検索、Web ページ、ダウンロード、ブラウザー操作はなし。スクリプトもオフラインです。
- **Listed sites**：一覧にあるサイトとそのサブドメインだけを開き、ダウンロードし、ブラウザーで使います。検索は使えます。スクリプトはオフラインです。
- **Any site**：どのサイトでも。サイトを一覧に入れると、ブラウザーでの扱いを個別に選べます。

## 許可済みフォルダー {#allowed-folders}

ワークスペースのメインフォルダー以外で coscribe が使えるフォルダーは、すべて 1 つの一覧 **Allowed folders**（**Settings › Workspaces › Manage**）にまとめられています。各フォルダーにはアクセスレベル（**Read only**、**Read and write**、**Read, write and delete**）があります。ワークスペースが触れられるのは、その **Allowed folders** ページで選んだ許可済みフォルダーだけです。**Use an allowed folder** で一覧から選び、**Add new folder…** で新しいフォルダーを追加します。新しいフォルダーは読み書き可能として一覧に入ります。

**Allowed folders** からフォルダーを外すと、すべてのワークスペースから外れます。抜いたドライブなど今見つからないフォルダーは印が付き、戻ってくればまた使われます。

会話が触れられないフォルダーを必要とすると、カードで尋ねます。[ほかのフォルダーへのアクセスを許可する](../use/approvals.md#give-access-to-another-folder) を参照してください。

## スクリプトと分離 {#scripts-and-isolation}

Windows では、スクリプトは分離された状態で動きます。会話のフォルダーしか使えず、そこでファイルを削除したり名前を変えたりできず、インターネットに出られるのはワークスペースの **Sites** が **Any site** のときだけです。coscribe は、分離がこの PC で機能するかを一度確認します。確認に失敗した場合はスクリプトがオフになります。**Scripts and commands** ページの **Run scripts without isolation** で、そのワークスペースについて再びオンにできますが、それに伴うリスクを負うことになります。
