워크플로는 고정된 단계로 이루어진 작업입니다. 글로 쓴 지침을 따르는 예약 작업과 달리, 워크플로는 매번 같은 단계를 실행하고 실행 중에 확인하므로, 실제로 하기 전에 무엇을 할지 볼 수 있습니다. 일정, 권한, 실행 보고서는 [예약 작업](scheduled-tasks.md)과 같습니다.

## 워크플로 만들기 {#make-a-workflow}

가장 쉬운 방법은 채팅에서 작업을 한 번 한 뒤 그것으로 워크플로를 만드는 것입니다.

- coscribe가 **Save this job?** 카드를 보여 줄 때나 **Task details** 패널에서 **Save as workflow**를 고릅니다.
- 또는 메시지 상자에 `/saveworkflow`를 입력합니다. 원하면 뒤에 이름을 붙입니다.

coscribe가 대화에서 단계 초안을 만듭니다. 살펴본 뒤 저장하세요.

처음부터 시작할 수도 있습니다. **Scheduled** › **New task** › **Build a workflow**로 가서 이름과 일정을 정해 저장한 뒤, 워크플로 페이지에서 단계를 추가합니다.

## 워크플로 페이지 {#the-workflow-page}

페이지에는 탭이 네 개 있습니다.

- **Overview**: 워크플로가 하는 일을 쉬운 말로 설명합니다. 언제 실행되는지, 무엇을 다루는지, 어디서 멈추고 사용자를 기다리는지, 무엇을 건드릴 수 있는지. **Show the flowchart**는 단계를 그림으로 그립니다.
- **Steps**: 단계 목록입니다. 여기서 단계를 추가, 변경, 재정렬합니다. **Flowchart** 보기로 바꿀 수도 있습니다.
- **Runs**: 지난 실행 목록입니다.
- **Settings**: 일정, 워크스페이스, 권한이 있습니다.

워크플로에 단계가 없으면 **Run now**는 회색으로 표시됩니다. 워크플로가 파일 같은 입력을 받는다면 먼저 그것을 요청합니다.

## 단계 종류 {#kinds-of-steps}

**Add a step**에는 다음 종류가 있습니다.

| 단계 | 동작 |
|---|---|
| **Tool** | 모델 없이 coscribe 도구 하나를 씁니다. |
| **Script** | 검토를 마친 고정 Python 스크립트를 실행합니다. |
| **Model** | 정해진 필드를 반환해야 하는 모델 호출 한 번. |
| **Agent** | 정한 한도 안에서 도구로 목표를 향해 작업합니다. 호출할 수 있는 도구, 바꿀 수 있는 폴더, 열 수 있는 사이트를 정합니다. |
| **Check** | 값이 조건을 만족하지 않으면 실행을 멈춥니다. |
| **Approval** | 승인할 때까지 멈춥니다. |
| **Ask you** | 뒤의 단계가 쓸 값을 입력할 때까지 멈춥니다. |
| **Wait** | 일정 시간, 특정 시각까지, 또는 파일이 나타날 때까지 멈춥니다. |
| **Remember** | 이미 처리한 항목처럼 다음 실행에 쓸 값을 보관합니다. |
| **Run a task** | 다른 작업을 한 단계로 실행하고 그 결과를 씁니다. |
| **If / otherwise** | 값에 따라 다른 단계를 실행합니다. |
| **Choose a path** | 값에 따라 고르는 여러 경로. |
| **At the same time** | 단계 레인 2~6개를 동시에 실행한 뒤 계속합니다. |
| **For each** | 목록의 항목마다 단계를 반복합니다. |

단계마다 실패했을 때의 동작을 고를 수 있습니다. **Stop the run**, **Skip it and go on**, **Run other steps instead** 중 하나입니다. 단계는 정해진 횟수만큼 다시 시도할 수도 있습니다.

## 단계가 동작하지 않을 때 {#autonomy}

웹사이트는 바뀌고, 파일은 실행마다 다릅니다. **If a step stops working** 설정은 그럴 때 AI가 얼마나 결정할 수 있는지 정합니다.

| 수준 | 동작 |
|---|---|
| **Fixed** | 저장된 단계만 실행합니다. 하나가 실패하면 실행을 멈추고 알려 줍니다. |
| **Self-healing** | 웹사이트가 바뀌었다면 AI가 지금 모습의 페이지에서 그 단계를 수행합니다. |
| **Proactive** | AI 단계가 자기 몫을 어떻게 할지 정합니다. 단계가 실패하면 AI가 단계 몇 개를 추가할 수 있으며, 무언가를 바꾸는 단계는 사용자를 기다립니다. |
| **Autonomous** | AI가 작업 전체를 자기 방식으로 할 수 있습니다. |

실행이 변화를 우회했다면 coscribe가 검토할 수 있도록 업데이트된 단계를 제안할 수 있어서, 다음 실행은 우회할 필요가 없습니다.

## 이벤트로 워크플로 시작하기 {#start-on-an-event}

모든 작업에 있는 일정 외에도, 워크플로의 **Frequency**는 다음이 될 수 있습니다.

- **Every few minutes**.
- **When a file arrives in a folder**: **Folder to watch**와, 원하면 **File name pattern**을 고릅니다. 새 파일이 생길 때마다 그 파일을 워크플로의 파일 입력으로 하여 실행합니다. 파일을 입력으로 받는 워크플로에서만 고를 수 있습니다.
- **When something new shows up in a connector**: 커넥터와 무엇을 물어볼지 고릅니다. coscribe가 몇 분마다 물어보고, 새 항목마다 실행을 시작합니다. 첫 확인 때는 이미 있는 것을 모두 본 것으로 처리합니다.
- **When a program sends it an event**: 같은 컴퓨터의 다른 프로그램이 coscribe가 보여 주는 주소로 키와 함께 요청을 보냅니다. **Wait for a sample**은 다음 이벤트를 보관해 두어, 그 이벤트의 어떤 필드로 입력을 채울지 고를 수 있게 합니다. 이 주소는 내 컴퓨터에서 온 요청만 받습니다.

coscribe가 닫혀 있는 동안 도착한 파일은 coscribe가 다시 시작할 때 실행을 시작합니다.
