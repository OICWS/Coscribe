# Generated Word files are marked in their language; Word and PowerPoint files use one East Asian face (shipped)

Why: in Word, the body text of a generated DOCX came out in SimSun while headings and tables
were in Microsoft YaHei, Chinese quotes were drawn as narrow Latin quotes, and styles that read the
theme fell to Japanese faces (MS Mincho, MS Gothic). Native tables in a page-built PPTX used the
theme's Calibri instead of the page's face. Found by opening the files in Word 16 and
PowerPoint on Windows and reading the fonts embedded in their PDFs.

## Shipped
- `write_docx` takes `language` (a tag such as zh-CN, zh-TW, ja-JP, ko-KR, en-GB): the model
  passes the language the person wants the document in; empty guesses it from the text (kana
  ja-JP, Hangul ko-KR, other CJK zh-CN, else en-US).
- `docx/_style.py`: the house style writes the East Asian face of that language by its local name
  (微软雅黑, 微軟正黑體, 游ゴシック, 맑은 고딕; Word ignored "Microsoft YaHei" in the document
  defaults). A Chinese, Japanese or Korean document marks its East Asian language, sets the
  `eastAsia` font hint so shared punctuation takes the East Asian face, and sets the theme's East
  Asian face and theme language in place of the template's Japanese ones; another language is set
  as the Latin language.
- `pptx/engine`: a native table without its own `font-family` takes the page's, and a deck built
  without a template fills the theme's empty East Asian face (`apply_cjk_font_fix`, as `write_pptx`
  already did).

## Not verified
- WPS on Windows; LibreOffice reads the Chinese face name through fontconfig.
