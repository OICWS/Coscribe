# Reasoning effort, part 2: the effort pill and slider next to the model (shipped)

Why: part 1 (#203) made the level something a conversation carries; the maintainer asked for the
control in the composer, between the model and the context ring, as Claude Code draws it (#202).

## Shipped
- `components/EffortPicker.tsx`: a pill with the level; its panel reads "Effort <level>", a ? with
  what effort trades off, Faster / Smarter, a six-stop track with a white thumb and the
  Recommended mark under Medium. Click, drag or the arrow keys change it; the choice is sent as
  `switch_model` with the same model and the new `effort`. When the model runs another level the
  panel says so ("This model runs it as Max"); a model with no effort setting shows the control
  disabled.
- Ultra (`components/UltraField.tsx`): a mosaic of 3 px squares sweeps in from the right in a
  second and settles into a field that is sparse and pale at the faster end and dense violet at
  the smarter end, each square twinkling on its own phase for as long as Ultra is chosen; drawn on
  a canvas, it shows the still field under the system's reduced-motion setting. The label is
  violet. A first version, a CSS gradient with a few sparks, was not what the maintainer's
  reference shows; this one was compared frame by frame with it.
- The slider shows a new level at once and counts the next step from it until the server confirms
  that same level: found live, quick key presses landed short, first because a step counted from
  the old level, then because the reply to an earlier step pulled the slider back. Four presses
  60 ms apart now land on Ultra. An error reply leaves no state, so a picked level is dropped
  after 3 seconds without confirmation.
- `state/reducer.ts` keeps `effort` and `effortRunsAs`; the reducer test checks them.
- Looked at live against a real backend (DeepSeek, no messages sent): Medium, High, and Ultra's
  sweep at 0.15, 0.4, 0.9, 2 and 2.6 s, with "This model runs it as Max".
