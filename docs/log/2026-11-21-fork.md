# /fork and Fork from here: a copy of a conversation opens as a new one (shipped)

Why: issue #1026, from the maintainer's list on #1003. Of the commands not built, only `/fork` is
done; `/export`, `/recap`, `/changes`, `/tasks` and `/template` are not (agreed 2026-11-21).

## Shipped
- `POST /api/threads/{id}/fork` (`web/routes/threads.py`) copies the conversation into a new one
  with the given title; `upto` stops it after the reply to that message, counted as edit and
  rewind count. Refused while a reply runs or an approval waits (409), for a task's run (400)
  and for a conversation that does not exist (404).
- The copy (`ConversationHistory.fork_into`, `conversation/history.py`) takes the current
  context's messages, with a call stopped mid-run answered as a stop does; what a /compact folded
  away stays with the original. `ThreadFiles.copy_for_fork` keeps the task list, the environment
  (and so the folders) and the title; the sidebar group comes along too.
- `/fork [name]` in the "/" menu; without a name the copy is "<title> (fork)". A finished reply's
  hover footer has a Fork button that copies up to that reply. Both open the copy at once.
- Tests: `tests/web/test_thread_history.py` (whole copy, copy up to a message, refusals);
  `frontend/tests/e2e/slash-menu.spec.ts` and `message-actions.spec.ts` (run here against the
  stub model).

## Not verified
- The Electron app on Windows; checked in Chromium on Linux only.
